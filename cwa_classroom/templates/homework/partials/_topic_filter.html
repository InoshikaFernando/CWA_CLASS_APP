{% comment %} Type-to-filter for the homework topic picker — shared by the week planner (schedule_detail) and "+ New Homework" (teacher_create). Include this ONCE per page, after the tree(s). It wires every element marked `data-topic-tree`, so a page with one tree per week needs no per-week script. What a tree has to provide: [data-topic-tree] the wrapper, one per picker [data-topic-filter] the search input [data-topic-filter-empty] the "nothing matches" line (starts hidden) [data-topic-filter-term] where the typed text is echoed label > [data-topic-name] a topic row (any label holding a checkbox) details[data-topic-group] > summary [data-topic-name] a group heading Matching reads the `data-topic-name` span only, never the row's whole text — otherwise "2" would match the "(2)" count beside every thin topic and the "2 selected" badge on every group. Filtering is a VIEW: rows are hidden, never unticked, and a hidden checkbox still posts its value. So a teacher who filters, ticks, filters again and saves keeps everything they chose — the one behaviour that would make a filter box worse than no filter box at all. {% endcomment %}
