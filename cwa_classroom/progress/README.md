# progress

Cross-subject progress reporting and dashboards. Aggregates data from the subject apps (`maths`, `coding`, …) into per-student and per-class views. Owns the JSON API used by client-side charts on the dashboards.

Mostly a **utility / view-only** app: the dashboards own no data, they read it from the subject apps. The one exception is `PeriodReport` (CPP-388), which has to be stored because an end-of-period report is a frozen snapshot rather than a live view.

## Key models

`PeriodReport` — one student's weekly / monthly / term progress report. `data` holds the whole computed snapshot (totals, per-topic accuracy, per-homework attempts, trend, awards); `notified_at` / `parent_emailed_at` track delivery and are what make the nightly generator idempotent. See [`docs/specs/CPP-388_period_progress_reports.md`](../docs/specs/CPP-388_period_progress_reports.md).

Everything else is read from:
- `homework.HomeworkSubmission`, `homework.HomeworkStudentAnswer` — the period report's primary source
- `worksheets.WorksheetSubmission`
- `maths.BasicFactsResult`, `maths.StudentAnswer`, `maths.TimeLog`, `maths.TopicLevelStatistics`
- `coding.StudentProblemSubmission`, `coding.CodingTimeLog`

## Period reports (CPP-388)

| Module | Responsibility |
|--------|----------------|
| `periods.py` | Which window a period covers, and which windows closed on a given day |
| `reports.py` | Builds the snapshot — totals, topics, attempts, trend, awards |
| `services.py` | Generates reports and delivers them (in-app notification; term email) |
| `pdf.py` | Renders a report to PDF with ReportLab, charts included |
| `access.py` | Who may read a report (student / parent / class teacher / HoI) |
| `views_reports.py` | List, detail (Chart.js) and PDF-download views |

Generated by cron:

```bash
python manage.py generate_progress_reports        # whatever closed today
```

## URL prefix & key routes

Mounted at the project root.

- `/student-dashboard/` — student's overall progress home
- `/student/<id>/progress/` — teacher view of a student's progress

Period reports live under the `progress:` namespace (`progress/report_urls.py`,
kept separate so the two routes above keep their un-namespaced names):

- `/progress/reports/` — `progress:period_report_list`
- `/progress/reports/<id>/` — `progress:period_report_detail`
- `/progress/reports/<id>/pdf/` — `progress:period_report_pdf`

## API

JSON endpoints for charts. Mounted at both `/api/` (legacy) and `/api/v1/` (canonical):

```python
path('api/v1/', include('progress.api_urls')),
path('api/',    include('progress.api_urls')),  # legacy, kept for compatibility
```

## Integration

In `settings.py`:

```python
INSTALLED_APPS = [..., 'progress', ...]
```

In root `urls.py`:

```python
path('', include('progress.urls')),
path('', include('progress.report_urls', namespace='progress')),
path('api/v1/', include('progress.api_urls')),
path('api/',    include('progress.api_urls')),  # legacy
```

## Dependencies

- **homework** — submissions and per-question answers; the period report's data source.
- **worksheets** — worksheet completions in the reported window.
- **maths** — quiz attempts, time logs, topic stats; `Question.topic` for the report's topic breakdown.
- **coding** — problem submissions and time logs.
- **classroom** — `Subject`, `Level`, `Topic`, `ClassRoom`, `Term`, `School`, `ParentStudent`, `Notification`, `email_service`.
- **accounts** — `CustomUser` for student/teacher identity.
- **reportlab** — server-side PDF rendering (pure Python; no system libraries).

## External services

SMTP, indirectly: the end-of-term parent email goes out through
`classroom.email_service.send_templated_email`.
